## 46 · Engine · The six performance and memory findings, fixed — and three stale selfcheck gates repaired

**2026-10-07 · The audit's numbers: `load_with` 57ms at 10k records; the write path ~0.78s at 10k and ~4.0s at 50k, of which the index refresh was 649ms (80%) — a second full load plus a full rebuild per edit; RSS 46MB at 10k growing to 180MB at 50k. **What was wrong.** 1 `ResolvedConfig` stored every record twice — a `records: Vec<Record>` beside the positioned store, cloned per record at load. 4 every formula re-parsed its expression text on each evaluation (content tree, metrics, views). 5/7 `views::query` cloned every record into its sort key set before the limit, and `resolve_with` cloned the outcome's warnings and records a second time. 2 a committed edit refreshed the index by reloading the whole plan and rebuilding every row — 10k-row work for a one-row change. 3 every read command paid the same retention as a write: `load_with` kept the raw bytes of every source file for the config's lifetime. 6 `TokenRegister::bundled` re-read and re-parsed tokens.json on every load; the shell loads per command.

**The fixes, in place.** 1 the duplicate `records` field is **deleted**; `positioned_records` is the single store, with accessors (`records_iter`, `record_count`, `records_by_type`, `record`) and every consumer migrated — the write path still owns its `PositionedRecord` untouched. 4 `ResolvedConfig.formulas: BTreeMap<String, Expr>` caches each parsed expression by its text at load, and the evaluator consults it before parsing (`resolve_segment`, `formula_scalar`). 5/7 the query sorts references with an id tie-break, truncates **before** materializing, and clones only the post-limit window; `resolve_with` moves what it already owns. 2 `index::refresh_after_commit` takes the committed `FileChange` set and updates rows incrementally — parse before/after of the changed `content/records/*.jsonl` only, DELETE the old ids, INSERT the new, update meta, one transaction; anything it cannot prove (types.json changed, foreign or corrupt cache, commit failure) falls back to the full rebuild or reports the warning, never guesses. 3 `load_readonly` skips byte retention; the dispatch read arm uses it for every command except `source`, whose file arm *is* the bytes. 6 the bundled register is parsed once per process and cached by path+len+mtime, so the shell pays one parse and the CLI (a process per command) pays nothing extra.

**Open** — the shell keeps no revision-keyed snapshot cache; that was deliberately left out (the engine is framework-free, and the measurements above say the read path no longer needs it). The bench crate lives outside the workspace by design; its recipe is this entry.

## 47 · Security · The eleven findings of the app audit — nine fixed, two accepted by design

**2026-10-07 · A full pass over the three surfaces (engine, shell, web UI) for what untrusted input could reach: a `.samprofile` someone sends you, a transaction id typed at the terminal, a plan's own record fields rendered as links and CSS. Nine fixes landed, each with a before/after proof; two findings are the product's own trust boundary, documented rather than locked.**

**Engine — path traversal (SAM-PATH-001/002/003).** `profile::fill_tree` wrote every `document.records` key from an imported `.samprofile` straight into `content/records/{key}.jsonl` — a hostile profile with the type id `../../pwned` wrote outside the staging root. Every key is now validated through `safe_type_id` before any write (test `a_hostile_type_id_cannot_escape_the_staging_root`; with the guard removed the import *succeeds*, which was the exploit proof). `transaction::restore_plan` interpolated an unvalidated `txid` into the backup read path — now a strict shape check mirroring `make_txid` (22 chars, 13 digits, hyphen, 8 hex), test `a_hostile_txid_cannot_retarget_the_backup_read`. And all three relative-path guards (`apply`'s batch check, `safe_type_id`, `validate_relative`) also reject `\`, which Windows treats as a separator — the traversal checks were forward-slash-only.

**Shell — the CSP was `null`** (`src-tauri/tauri.conf.json`): the webview ran with Tauri's permissive default, so any injected script could reach `ipc:`. Now a real policy: `default-src 'self'`, `script-src 'self'`, `style-src 'self' 'unsafe-inline'` (Svelte's inline style attributes need it; script is the protected class), `img/font-src 'self' data:`, `connect-src 'self' ipc: http://ipc.localhost`, `object-src 'none'`, `base-uri`/`form-action 'self'`. The two inline `<script>` IIFEs in `ui/index.html` (theme/size bootstrap) moved to a static same-origin `ui/public/boot.js` — same pre-paint semantics, no inline script left to exempt.

**UI — six smaller fixes.** `safeUrl` (`ui/src/safeUrl.ts`): every anchor bound to a record's `url` field goes through one scheme check (`https?:` only) — applied at both construction sites (`Reference.svelte`, the composer's `Host.svelte`) and all three library variants; a `javascript:alert(1)` record now renders as a card with no link (verified rendered in the browser harness, variant B: the sibling `https:` record renders an anchor, the hostile one does not). The guard itself is null-safe — the first version crashed the panel on a null `url` because callers hand it whatever the record carried. `endpoint()` in `ipc.ts` same-origin-checks the harness-provided endpoint. The three `querySelector` sites in `reviews-queue/B.svelte` escape their ids with `CSS.escape`. `appearance.ts` validates both the name (`--token` shape) and value of every CSS custom property before it touches `style`, mirroring the engine's own token names; `boot.js` carries the same two checks. `reviews-recall/C.svelte` snapshots with `replaceChildren(cloneNode)` instead of an `innerHTML` re-parse. The `__SAM_RENDER_DUMP__`/`__SAM_APP__` hooks install only in dev or the web harness — in a packaged window they were an engine write path (`run()` dispatches any registry id) available to any script that lands in the page.

**A fix that broke its own gate, and the correction.** The first `safeToken` name pattern (`^--[a-z0-9-]+$`) was written against a survey of `theme.rs` that missed the `$dark` overlay's emitted names: `appearance.resolve` ships `--sh-$dark.1…ink` (five shadow tokens per theme), and the narrow pattern silently dropped them — theme flips lost the dark shadows, and the gates' `setTheme` lightness probe timed out because `--card` never resolved as expected. The name pattern now accepts the engine's real vocabulary (`^--[\w$.-]+$`, both in `appearance.ts` and `boot.js`'s cache loop); every one of the 115 names the engine emits in both modes passes, and the value checks (`url(`, `expression(`, `javascript:`) are unchanged. Re-deriving an allow-list from the emitter — not from a reading of one file — is the lesson; `appearance.resolve`'s own output is now the check's fixture.

**The gate run surfaced a second, older bug — a registry race on the rail's System disc.** The gates open the System surface by clicking the rail the moment a destination disc paints; the session fetches its command registry *after* the views, so a click in that first ~100ms found no registry entry for `app.openSystem`, fell through to an engine dispatch, and the engine answered `no GUI` — the click died and the gate timed out on `.sys-groups`. Reproduced four-for-four on fresh loads (click works, `run('app.openSystem')` works, the raced click does nothing). `run()` now recognises the eleven presentation ids (§4.9's fixed list, mirrored as a module-level table) without waiting for the registry; the registry still refines every other id. Four fresh-load clicks after the fix: four opens.

**Accepted by design.** SAM-BOUNDARY-001: the web harness's `dispatch` can point at any plan directory — that is the picker flow's documented trust boundary, not a hole. SAM-UI-006: localStorage keeps plan paths and timer labels in plaintext — local-app metadata on the user's own machine.

**Verification** — `cargo test -p sam-core` 173 lib + 8 integration green, no warnings; `sam selfcheck` 61/61 against the fresh release build; UI `tsc --noEmit` clean, `vite build` clean (bundle greps: `safeUrl` regex present, hooks assigned only inside the `transport()==='web'` guard, `CSS.escape` present, no inline scripts); browser harness smoke: app mounts on the production build, `boot.js` sets theme/size pre-paint, hooks answer under the web transport, and the hostile-URL record renders as text while its `https:` sibling renders as the only anchor on the page.
